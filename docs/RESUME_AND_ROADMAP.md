# StockAgent — 简历写法与开发路线

---

## 一、简历写法

### 项目名称

**StockAgent — AI 驱动的自主股票投资 Agent**

### 一句话描述（放在项目列表第一行）

自主设计并实现了一个连接券商账户的 AI 投资 Agent，集成多维分析引擎、三层记忆系统和风控体系，支持从信号生成到自动交易的完整闭环。

### 详细描述（面试时展开讲）

**项目背景**：为解决个人投资中信息过载、情绪化交易、缺乏系统性风控的问题，设计了一个自主运行的投资 Agent，能够持续监控持仓、分析市场、执行交易。

**技术亮点**（按优先级排列）：

1. **三层持久记忆系统** — 参考生产级 Agent 框架（Hermes）的记忆管理机制，设计了三层记忆架构：长期记忆（每轮推理注入，防止重复犯错）、研报语料库（FTS5 全文检索，按需查询）、交易决策日志（含完整上下文和结果追踪），支持跨会话学习与策略复盘。

2. **经纪商抽象层** — 定义统一的 `BaseBroker` 接口，实现模拟经纪商（几何布朗运动价格模型）和 IBKR 实盘经纪商两种实现，通过工厂模式按配置无缝切换。整个分析和交易系统完全与具体经纪商解耦。

3. **四维信号分析引擎** — 技术面（SMA/EMA、RSI、MACD、布林带）、基本面（估值、成长、盈利能力、财务健康度）、情绪面（新闻 NLP、VIX）、动量面四个独立分析器各产出 -1 到 1 的评分，通过可配置权重合成综合信号，并自动检测信号一致性。

4. **预交易风控引擎** — 8+ 条硬性规则在订单提交前拦截：持仓集中度上限、单笔交易上限、日亏损熔断、交易次数限制等。风控引擎还会计算风险调整后的安全仓位，而非简单拒绝。

5. **代理编排架构** — `agent.py` 作为中央编排器，协调数据采集、分析、风控、执行、通知五个子系统。支持定时运行（盘前/盘中/盘后）和手动 CLI 操作。

**技术栈**：Python 3.11 · SQLite FTS5 · ib_insync · yfinance · YAML 配置 · 多渠道通知（飞书/Telegram/CLI）

**项目规模**：29 个源文件，~6300 行 Python 代码

### 面试高频问题预判

| 问题 | 回答要点 |
|------|----------|
| 为什么设计三层记忆而不是一层？ | 一层会信息过载。LTM 压缩到 2KB 注入每轮推理，研报按需查，交易日志用于复盘。各层用途不同、访问频率不同。 |
| 经纪商抽象层有什么好处？ | 测试时用模拟经纪商（零成本），上线时改配置切 IBKR。整个系统不知道底层是哪个经纪商。 |
| 风控引擎怎么防止过度交易？ | 日交易次数上限、日亏损熔断、单笔限额、大额交易确认。不是事后止损，而是事前拦截。 |
| 信号不一致时怎么处理？ | composite analyzer 检测一致性，不一致时降低置信度，风控引擎会缩小仓位或拒绝交易。 |
| 和量化交易有什么区别？ | 这是 Agent 架构（有记忆、有推理、有复盘），不是纯信号回测。重点在 agent 设计而非 alpha 发现。 |

## 三、开发路线图

### Phase 1：验证可用性（1-2 周）⭐ 最优先

**目标**：确认代码能跑通，核心流程走通。

```bash
# 1. 安装依赖并跑通基本流程
pip install yfinance pandas pyyaml requests ta
python cli.py status      # 模拟账户加载
python cli.py analyze     # 全持仓分析
python cli.py analyze AAPL  # 单股分析
python cli.py report      # 生成日报

# 2. 写单元测试
tests/
├── test_config.py        # 配置加载
├── test_broker_sim.py    # 模拟经纪商
├── test_memory.py        # 记忆系统
├── test_technical.py     # 技术指标
├── test_fundamental.py   # 基本面评分
├── test_risk.py          # 风控规则
└── test_executor.py      # 交易流程
```

**为什么最优先**：代码没跑过就不知道有没有 bug。简历上写 "tested with X% coverage" 比 "未测试" 强很多。

### Phase 2：LLM 集成（2-3 周）⭐ 核心差异化

**目标**：让 Agent 真正"智能"起来。

```
当前：规则驱动的分析（if RSI > 70 → overbought）
目标：LLM 驱动的分析（读取财报 → 生成投资论点 → 评估风险）
```

具体实现：
- 用 LLM 解读 earnings call transcripts
- 用 LLM 生成投资论点和风险评估
- 用 LLM 对新闻进行深度情绪分析（而非关键词匹配）
- Agent 用 LLM 做决策推理（chain-of-thought）

```python
# 新增 modules
analysis/llm/
├── earnings_analyzer.py    # 财报解读
├── news_analyzer.py        # 新闻深度分析
├── thesis_generator.py     # 投资论点生成
└── risk_assessor.py        # 风险评估
```

**为什么重要**：这是从 "量化脚本" 到 "AI Agent" 的关键跃迁。没有 LLM，这只是一个规则引擎，不是 Agent。

### Phase 3：回测框架（2-3 周）

**目标**：用历史数据验证策略。

- 历史价格数据下载和管理
- 回测引擎（模拟历史交易）
- 绩效指标计算（夏普比率、最大回撤、胜率）
- 参数优化（权重、阈值调优）

```
新增 modules
backtest/
├── engine.py              # 回测引擎
├── metrics.py             # 绩效指标
├── optimizer.py           # 参数优化
└── data_manager.py        # 历史数据管理
```

**为什么重要**：没有回测就没有说服力。面试官会问 "收益怎么样"，回测数据是最好的回答。

### Phase 4：CI/CD + 代码质量（1 周）

- GitHub Actions CI（lint + test + coverage）
- pre-commit hooks（black, ruff, mypy）
- 测试覆盖率 badge

### Phase 5：Web Dashboard（3-4 周）可选

- FastAPI 后端 + WebSocket 实时推送
- React 前端：持仓概览、分析结果、交易日志
- 部署到 VPS

## 四、优先级矩阵

```
                高价值
                  │
    Phase 2       │      Phase 5
    LLM 集成     │      Web Dashboard
                  │
  ────────────────┼────────────────
                  │
    Phase 1       │      Phase 4
    测试验证      │      CI/CD
                  │      Phase 3
                  │      回测框架
                低价值

    ◄── 难度低          难度高 ──►
```

**推荐顺序**：Phase 1 → Phase 2 → Phase 3 → Phase 4 → Phase 5

Phase 1 是地基（不验证能跑就没意义），Phase 2 是灵魂（LLM 让它成为真正的 Agent），Phase 3 是证据（回测数据证明价值）。
